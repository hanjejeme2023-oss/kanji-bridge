1. **Judging (D71 item 2, D76 items 1-2), one shared function** used by カード (Part B), the 音のルール test and the 字体 quiz (Part C). Input: the typed text, the language, the list of accepted readings (one for カード and 音のルール; the row's readings for 字体), plus the `vi_alt` values for Vietnamese word answers.
   - **Chinese:** NFD, remove tone marks (U+0304, U+0301, U+030C, U+0300), `ü`/`v`/`u:` → `ü`, casefold, remove spaces, apostrophes (`'` `’`) and hyphens; compare with each reading treated the same way.
   - **Vietnamese:** casefold, NFC, then **Telex conversion per syllable** (maximal run of letters), then NFD, remove only the five tone marks (U+0301, U+0300, U+0309, U+0303, U+0323), NFC, remove spaces; compare with each reading and each `vi_alt` treated the same way (no Telex step for those). ă â ê ô ơ ư đ must match (`a` for `â` is wrong). Telex (UniKey style): `dd` → đ; `aa ee oo` → â ê ô; `aw ow uw` → ă ơ ư; `uow` and `uwow` → ươ; a `w` typed later in the syllable (after the vowel or the final consonant) applies to the syllable's vowel nucleus (`uo` → ươ, else the last of `a`/`o`/`u`); a lone `w` with no `a`/`o`/`u` before it → ư; the tone keys `s f r x j z` are removed when they come after the syllable's first vowel letter (an initial `s`, `r`, `x` is a consonant). Text that already has Vietnamese marks (a Vietnamese keyboard) passes through unchanged.
   - **Several readings (字体 only):** split the typed text on `,` `/` `，` `／` `、`; drop empty parts; right when at least one part remains and every part matches one accepted reading. One reading alone is right; listing all is not required.

2. **Tone hint before typing (D71 item 2, D76 item 1):** shown wherever a Chinese or Vietnamese answer is typed (card front here; rule test and 字体 quiz in Part C). Several readings: each reading's hint, joined by 「 / 」 (還 「2声 / 2声」, 地 「軽声 / 4声」, 行 「huyền / huyền」). A word without `pt` shows no Chinese hint (none of them is typed; D76 item 9).

3. **読解 (D71 item 8, D76 item 5):** tapping a linked word marks it 「わからない」 (adds its `word_id` to `kb_unknown`, in addition to opening its detail as now); the passage's marked words are listed under it for review (same word-detail behaviour on tap); marks clear only through `clearUnknown` (Part C item 5). **Read mark:** when the user leaves a passage (selects another passage or switches tab), its `passage_id` is added to `kb_read` (array of `passage_id` left at least once). A passage's selector pill shows ✓ when its id is in `kb_read` **and** none of its linked words is in `kb_unknown`. So a passage never marked gets ✓ on leaving; a marked one gets ✓ once its marks are cleared; the ✓ disappears if one of its words is marked again (also from another passage). ✓ is computed on render, not stored.
